# 安全文件传输软件设计与实现

这是中国科学院大学「软件与系统安全」课程的实验项目。系统在 TLS 1.3 双向认证连接上运行自定义文件传输协议，提供命令行客户端和本地浏览器界面。不同账号使用独立目录，同一账号可并行传输多个文件，并在连接中断后继续已保存的分块。

- 使用客户端证书的 SHA-256 指纹确定账号。客户端同时验证服务端证书和服务端名称。
- 支持列目录、上传、下载、断点续传和批量传输。浏览器可暂停任务，并查看恢复偏移和校验结果。
- 发布文件前校验文件长度和 SHA-256 摘要。服务端以原子方式发布上传文件，保留已有同名文件。
- 服务端按账号限制连接数、文件配额和双向载荷速率。macOS 可用隔离入口限制服务进程的文件访问范围。

## 快速开始

需要 **Node.js 24 或更新版本**、随 Node.js 提供的 npm，以及 PATH 上可执行的 `openssl`。在源码根目录执行以下三条命令。

```bash
npm ci
npm run build
npm run setup
```

编译产物位于 `dist/`。初始化会创建 `runtime/`，其中包含演示用 CA 证书、服务端证书、Alice 和 Bob 的客户端证书、连接配置及各自的存储目录。初始化需要一个尚未存在的目标目录，已有 `runtime/` 可直接用于启动。

在第一个终端启动文件服务。

```bash
npm start
```

看到 `LISTEN 127.0.0.1:9443` 后即可连接。使用 macOS 进程隔离时，在该终端运行以下命令。

```bash
node scripts/start-isolated.mjs runtime/server.json
```

两条启动命令使用同一个服务端配置和端口，每次启动其中一种。隔离入口依赖 macOS 的 `sandbox-exec`，要求监听 `127.0.0.1`，以及配置中的存储和证书路径位于运行目录内。演示在 Apple 芯片 Mac 上以 Node.js 24.22.1 验证。

## 浏览器操作

保持服务端运行，在另一个终端启动浏览器适配器。

```bash
npm run ui
```

打开终端输出的**完整链接**，并点击页面中的「连接」。适配器默认监听 `127.0.0.1:8787`，链接片段携带当前进程生成的访问令牌。打开页面后令牌片段会从地址栏移除，刷新当前标签页可以继续使用该令牌。适配器重启后，从终端重新打开新链接。

1. 在「上传文件」中选择或拖入文件。多选文件会进入队列，单文件可指定远端文件名。
2. 在「远端文件」中点击单个文件的「下载」，或勾选多项后点击「下载所选」。
3. 在传输队列中点击「暂停」，随后点击「重试」。任务会根据检查点和文件版本决定续传起点。
4. 查看「传输记录」中的字节数、SHA-256 摘要和恢复偏移。批量下载时按浏览器提示保存各文件。

浏览器适配器保留一条控制连接查询目录和保活，最多同时运行三个上传或下载任务。改用 Bob 账号时，先结束原适配器，随后执行 `node dist/ui.js runtime/bob.json`。

## 命令行操作

在另一个终端以 Alice 的证书登录。

```bash
node dist/client.js runtime/alice.json
```

连接成功后显示 `CONNECTED TLSv1.3`。在客户端交互提示符下输入以下命令。

| 命令 | 行为 |
| --- | --- |
| `list` | 列出当前账号已完成的文件和字节数 |
| `put <本地文件> [远端名]` | 整文件上传，省略远端名时使用本地文件名 |
| `get <远端名> [本地文件]` | 整文件下载，省略本地路径时使用远端文件名 |
| `put-resume <本地文件> [远端名]` | 分块上传，已有检查点时从确认的偏移继续 |
| `get-resume <远端名> [本地文件]` | 分块下载，远端版本匹配时从本地检查点继续 |
| `quit` | 等待服务端确认并关闭连接 |

以下命令在 shell 中创建一个样例并启动客户端。

```bash
printf 'SFT demo\n' > sft-demo.txt
node dist/client.js runtime/alice.json
```

在客户端中执行以下操作。

```text
put-resume sft-demo.txt
list
get-resume sft-demo.txt sft-demo-download.txt
quit
```

随后在 shell 中运行 `cmp sft-demo.txt sft-demo-download.txt` 比对内容。续传命令输出中的 `RESUMED` 是本次开始时已保存的字节数，首次传输为 0。连接中断时，重连并使用同一源文件、远端文件名和目标路径重新执行续传命令。包含空格的本地路径用双引号括起。

另开终端运行 `node dist/client.js runtime/bob.json` 可查看 Bob 的目录。Alice 上传的文件只列在 Alice 的账号下。远端文件名为 1–64 个字符，以英文字母或数字开头，之后可使用英文字母、数字、点、下划线和连字符。末尾的点及保留设备名会被拒绝。

## 配置与限制

| 位置 | 配置 | 说明 |
| --- | --- | --- |
| 初始化环境变量 | `SFT_PORT` | 写入服务端及两个客户端配置的端口，默认 9443 |
| `runtime/server.json` | `host`、`port` | 文件服务的监听地址和端口，默认 `127.0.0.1:9443` |
| `runtime/server.json` | `ca`、`cert`、`key` | CA 证书、服务端证书和私钥路径，相对于配置文件目录解析 |
| `runtime/server.json` | `users`、`dataDir` | 账号名到客户端证书指纹的映射，以及账号存储根目录 |
| `runtime/server.json` | `bandwidthBytesPerSecond` | 按账号配置每秒文件载荷字节数 |
| `runtime/alice.json`、`runtime/bob.json` | `host`、`port`、`servername`、`ca`、`cert`、`key` | 服务地址、用于核验证书的服务端名称、CA 证书及账号凭据 |
| 适配器环境变量 | `SFT_UI_PORT` | 浏览器适配器的回环端口，默认 8787 |

初始化配置中，Alice 为 **8 MiB/s**，Bob 为 **2 MiB/s**。单账号允许配置 2–64 MiB/s，数值单位是字节每秒，未配置的账号默认 8 MiB/s。上传和下载使用同一个账号额度，因此多开连接不会增加该账号的配置速率。修改配置后重启对应进程。

服务端最多接受 12 条连接，每个账号最多 4 条已认证连接。每个账号有 16 个文件名配额，已完成文件和未完成的上传共用配额。单文件上限是 8 MiB，续传分块上限是 512 KiB。TLS 握手时限为 5 秒，服务端处理一轮请求的时限为 45 秒，每条连接每 60 秒最多处理 120 个请求。

## 通信与存储设计

```mermaid
flowchart LR
    Browser["本机浏览器"] <-->|"回环 HTTP 与访问令牌"| Bridge["浏览器适配器"]
    CLI["命令行客户端"] <-->|"TLS 1.3 双向认证"| Server["文件服务端"]
    Bridge <-->|"TLS 1.3 控制连接与任务连接"| Server
    Server --> Alice["Alice 私有目录"]
    Server --> Bob["Bob 私有目录"]
```

**协议分帧。** 每帧由 12 字节定长头、UTF-8 JSON 控制头和可选的二进制载荷组成。定长头依次包含 `SFT1` 标识、4 字节控制头长度和 4 字节载荷长度，长度字段采用大端字节序。接收端按声明长度从 TCP 字节流中读取，控制头上限为 4 096 字节。单条连接按顺序发送请求和接收响应，控制连接在空闲时发送应用层心跳。

**断点续传。** 上传端用 `put-begin` 获取已确认的偏移，从该位置依次发送 `put-chunk`，最后用 `put-finish` 校验并发布。服务端把检查点保存在对应账号的 `.sft-partial` 目录中。下载端通过 `get-info` 确认文件大小和摘要，再从检查点位置请求 `get-chunk`。命令行下载检查点在目标文件旁，浏览器下载检查点由适配器写在账号配置旁的私有缓存目录。

**认证与隔离。** TLS 证书验证和指纹映射确定账号，文件操作限定在该账号目录。macOS 隔离入口进一步把服务进程的业务写入范围限制在存储目录。浏览器适配器监听回环地址，检查请求主机、来源和访问令牌。限速和连接约束覆盖本项目的应用层资源。

## 源码导览

| 文件 | 职责 |
| --- | --- |
| `src/protocol.ts` | SFT1 分帧、读取边界、文件名和摘要校验 |
| `src/server.ts` | TLS 认证、账号连接计数、请求调度和处理时限 |
| `src/storage.ts` | 私有目录、文件名配额、上传检查点和原子发布 |
| `src/bandwidth.ts` | 为同一账号的并发会话和双向载荷预留传输时间 |

| `src/transfer.ts` | 客户端分块上传、分块下载、检查点和完整性校验 |
| `src/client.ts` | 命令行解析、交互循环、本地文件读写 |
| `src/ui.ts` | 本机 HTTP 适配器、控制连接和传输任务连接 |
| `ui/index.html`、`ui/app.js`、`ui/style.css` | 页面结构、队列交互、浏览器校验和样式 |
| `scripts/setup.mjs`、`scripts/start-isolated.mjs` | 初始化演示环境、启动 macOS 隔离服务 |
| `tests/*.test.mjs` | 协议、存储、续传、适配器与隔离的自动化验证 |

## 测试

```bash
npm run build
npm test
```

测试使用 Node.js 内置测试运行器，启动临时回环服务并生成独立的证书和数据目录。可在编译后用 `node --test tests/transfer.test.mjs` 单独运行客户端续传用例。

| 测试文件 | 验证内容 |
| --- | --- |
| `protocol.test.mjs` | 二进制分帧、合法边界、格式校验和文件名约束 |
| `sft.test.mjs` | 认证、命令行往返、多账号与同账号并发、续传、限速、配额和保活 |
| `transfer.test.mjs` | 中断后从已保存位置恢复、远端版本变化和摘要错误 |
| `ui.test.mjs` | 本地访问控制、浏览器适配器接口、并行队列和任务取消 |
| `isolation.test.mjs` | macOS 隔离进程的目录权限和 TLS 文件往返 |

本项目在 macOS 上完成过 44 项自动化测试，并在 Chrome 中实测了批量下载、暂停重试和 SHA-256 校验。隔离测试在其他系统上会跳过。

## 常见问题

- **初始化报目录已存在。** 用现有配置启动，或生成到新的运行目录。例如已有 `runtime/` 时可执行 `SFT_PORT=9444 npm run setup -- runtime/demo-9444`，再用 `node dist/server.js runtime/demo-9444/server.json` 启动，并使用同一目录内的客户端配置。
- **服务提示端口被占用。** 停止占用该端口的项目进程，或在新的运行目录用不同的 `SFT_PORT` 初始化。适配器端口可用 `SFT_UI_PORT=8788 npm run ui` 修改。
- **页面提示会话无效。** 打开当前适配器终端打印的完整链接。适配器每次启动都生成新令牌。
- **TLS 连接失败。** 检查服务是否已启动、端口是否与客户端配置一致，以及配置和证书是否来自同一运行目录。重新初始化后应成套使用新配置。
- **下载提示本地文件已存在。** 命令行客户端保留已有文件。指定一个新的目标路径重试。
